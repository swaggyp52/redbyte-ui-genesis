# Basys 3 Mapping

## Overview

Basys3 export turns RedByte IO mappings into three coupled artifacts: grouped or scalar entity ports in `top.vhd`, matching `get_ports` references in `top.xdc`, and student-facing mapping guidance in the export README and bring-up files. This note exists so Vivado-facing naming, pin assignment, and clock policy stay consistent across those outputs.

## Canonical Shape / Contract

- `ioMapping.inputs` and `ioMapping.outputs` are the authority for Basys3 boundary exposure.
- Basys3 alias groups such as `SW[n]`, `LED[n]`, `AN[n]`, and `SEG[n]` may collapse into vector entity ports when the export model detects grouped aliases.
- Student-facing labels may become entity/XDC port names only after Basys3 export sanitizes them into legal VHDL basic identifiers.
- `top.xdc` must reference the exact exported entity port names or vector-bit refs generated by the export model.
- `CLK` / `CLK100MHZ` / `W5` is the only Basys3 input that should receive `create_clock` and clock-buffer treatment by default.
- `SW*` and `BTN*` ports are board controls, not clocks. Their XDC refs must carry `CLOCK_BUFFER_TYPE NONE` so Vivado does not infer BUFGs on non-CCIO pins.

## Rules

- Port-name sanitization must collapse repeated separators, trim edge underscores, and prefix non-letter-leading names before using them in `top.vhd` or `top.xdc`.
- XDC generation must apply `CLOCK_BUFFER_TYPE NONE` to every switch and button input port regardless of whether the overall design is combinational, latch-based, or clocked.
- Grouped vector refs in XDC such as `SW[1]` or `LED[0]` must map back to declared VHDL entity base ports.
- Export validity is not enough on its own; Basys3 mapping changes must be proven against real Vivado synthesis and implementation when the clocking or naming contract changes.

- Sanitization rules for other artifact layers that also mint identifiers from student text should be aligned with this Basys3 contract rather than drifting independently.
