# Verify Hint System

**File:** `packages/rb-apps/src/apps/ide/verifyHints.ts`
**Tests:** `packages/rb-apps/src/apps/ide/__tests__/verifyHints.test.ts`
**Status:** Stable

---

## Purpose

When a Verify run produces FAIL, `getVerifyHint(ctx)` selects the single most actionable hint to surface. The function returns a `string` or `null` - exactly one hint fires, or none.

---

## Context Type

```typescript
interface VerifyHintContext {
  hasDff: boolean;
  mappingComplete: boolean;
  allTicksFail: boolean;       // failCount === totalRows
  onlyFirstTickFails: boolean;
  mismatch: { expected: string; actual: string } | null;
  hasFloatingOutputWarning: boolean;
  floatingSignals?: string[];
  pattern?: VerifyFailurePatternSummary | null;
  vectorsAreAutoGenerated?: boolean;
}
```

---

## Priority Chain (first match wins)

| # | Condition | Hint trigger |
|---|---|---|
| 1 | `!mappingComplete` | Unmapped pins -> always read 0 |
| 2 | `hasFloatingOutputWarning` | Floating output signals |
| 3 | `pattern?.kind === 'repeated-output'` | Single output fails every tick it is checked |
| 4 | `pattern?.kind === 'grouped-peer'` | Multiple outputs fail together |
| 5 | `pattern?.kind === 'delayed'` | Circuit passes then diverges |
| 6 | `allTicksFail && hasDff` | Sequential circuit, all ticks fail |
| 7 | `allTicksFail && !hasDff && !vectorsAreAutoGenerated` | Combinational, user-authored vectors, all fail -> "loaded example" hint |
| 8 | `allTicksFail` (catch-all) | Any remaining allTicksFail case -> "Every tick fails" |
| 9 | `onlyFirstTickFails` | First tick only |
| 10 | `hasDff && mismatch expected=1 actual=0` | Flip-flop output stuck low |
| 11 | `hasDff && mismatch expected=0 actual=1` | Flip-flop output stuck high |

---

## Critical Rule: Priority Ordering

> When adding a new specific condition, audit every lower-priority catch-all that the new rule might shadow. Existing tests for catch-all branches must be updated to include the flag that bypasses the new specific condition.

This was violated when `vectorsAreAutoGenerated` was added at priority 7 - see [[BUG-002 VerifyHints Priority Inconsistency]].

---

## Pattern System

`deriveVerifyFailurePattern(input)` computes a `VerifyFailurePatternSummary` from run statistics:

```typescript
type VerifyFailurePatternKind =
  | 'all-run'
  | 'startup'
  | 'repeated-output'
  | 'grouped-peer'
  | 'delayed'
  | 'selected-case';
```

The pattern is passed into hint context via `VerifySurface` -> `getVerifyHint`.

---

## Wire Path in VerifySurface

```text
lastRun.report -> deriveVerifyFailurePattern() -> pattern
hasDff (prop)
mappingComplete (prop)
allTicksFail = (totalRows > 0 && failCount === totalRows)
onlyFirstTickFails = (failingRows[0]?.tick === 0 && failingRows length === 1)
-> getVerifyHint(ctx) -> hint string shown inside Verify's fail-analysis drawer when that drawer is open
```
