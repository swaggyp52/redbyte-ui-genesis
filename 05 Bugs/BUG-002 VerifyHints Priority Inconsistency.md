# BUG-002 — VerifyHints Priority Inconsistency

**Status:** Fixed
**Severity:** Test failure (1 test, wrong hint fired)
**Discovered:** 2026-03-25 autonomous test run
**Fixed in:** `packages/rb-apps/src/apps/ide/__tests__/verifyHints.test.ts`

---

## Problem

Test `"fires when allTicksFail is true"` expected the hint to contain `'Every tick fails'` but received:

```
'All vectors failed. If you loaded this example without modifying the circuit,
the expected outputs may not match your current design...'
```

---

## Root Cause

The `HINTS` array in `verifyHints.ts` uses priority ordering — first match wins. When `vectorsAreAutoGenerated` was added as a priority-2 rule, it inserted a more specific case *before* the original catch-all at priority 3:

| Priority | Condition | Hint text |
|---|---|---|
| 1 | `allTicksFail && hasDff` | "All vectors failed on a sequential circuit..." |
| 2 | `allTicksFail && !hasDff && !vectorsAreAutoGenerated` | "All vectors failed. If you loaded this example..." |
| 3 | `allTicksFail` | "Every tick fails..." |

The test fixture (`BASE`) did not set `vectorsAreAutoGenerated`. In TypeScript, `!undefined === true`, so priority 2 fired instead of priority 3.

The test was written before priority 2 existed. After `vectorsAreAutoGenerated` was added to the hint chain, the test became silently wrong — it still passed the condition check but fired the wrong branch.

---

## Fix

Rewrote the test to explicitly cover both branches:

```typescript
// Priority 3: auto-generated vectors bypass the "loaded example" hint
it('fires when allTicksFail (auto-generated, no DFF)', () => {
  const hint = getVerifyHint({ ...BASE, allTicksFail: true, vectorsAreAutoGenerated: true });
  expect(hint).toContain('Every tick fails');
});

// Priority 2: user-authored vectors fire the "loaded example" hint
it('fires auto-generated-example hint when vectors are not auto-generated', () => {
  const hint = getVerifyHint({ ...BASE, allTicksFail: true, vectorsAreAutoGenerated: false });
  expect(hint).toContain('All vectors failed');
});
```

---

## System Truth Captured

> When adding a new priority branch to `HINTS`, always audit existing tests that rely on catch-all branches lower in the array. A new specific condition silently steals the match.
