## Current Unified Workbench v3 RC Source (2026-07-22)

- **Flow authority:** The full RedByte-owned student flow is `Project -> Design -> Verify -> Map Pins -> Export`. Import is a reviewed Upload -> Review -> Apply recovery utility, not a sixth stage.
- **Verify authority:** Named testbench documents own their combinational cases or sequential timeline and their browser-local sequential policy. Policy includes mode, cycles, edge, reset behavior, clock/control identity, execution model, and start level; pulse steps retain rising/falling/high/low meaning. Save/reload, rename, duplicate, library repair, Import recovery, and compatible Design edits preserve that intent. The policy stays outside portable `RBProject`, while one shared materialized execution-vector sequence drives runtime Verify, bring-up expectations, and generated `testbench.vhd` together with the resolved clock/schedule projection. Auto `runCycles`, an automatic reset sequence, resolved clock data, starting level, and authored stimulus may therefore change generated bytes, Export freshness, and prior-receipt authority.
- **Sequential execution truth:** Manual/custom rows drive the resolved clock with the authored value and are sampled as settled steps. In the supported rising-edge model, only an authored low-to-high transition captures state; repeated high, high-to-low, repeated low, and flat-low stimulus hold rising-edge state. An authored falling transition is supported stimulus, not falling-edge-triggered capture. Auto board-clock mode materializes cycle 0 and the selected `runCycles`; each Auto report row and generated VHDL assertion is sampled after its rising edge. When `auto-sequence` reset applies, reset is asserted in materialized cycle 0 and deasserted in later cycles rather than injected as a hidden runtime prelude. Manual/custom mode likewise adds no hidden reset.
- **Mapping/package authority:** One semantic projection links logical signal -> artifact port -> Basys3 resource -> package pin -> exact XDC line. It drives Map Pins status/conflicts, Export views and artifacts, the canonical embedded manifest, and manifest-first re-import. Logical IDs, artifact ports, board resources, and package pins remain separately labeled.
- **Export trust authority:** Export keeps three exact axes: structural `blocked` / `downloadable`, `verificationTrust` `unverified` / `draft` / `trusted`, and action `not-downloaded` / `downloaded`. Verify evidence currentness (`current`, `missing`, `stale`, or `failed`) remains an upstream evidence classification, not an Export enum. A download never promotes `verificationTrust`. The first viewport answers **What should I submit?** while leaving course/LMS policy to the instructor.
- **Import authority:** `project.rbproj.json` is authoritative when present and carries the exact generated HDL/XDC projection. Canonical parser-owned bit identities such as `SW[1]` / `LED[1]` may receive pins from the manifest's embedded XDC only. Loose sibling XDC is non-authoritative. Supported generated concurrent-assignment HDL can reconstruct; arbitrary behavioral HDL remains partial or blocked.
- **Interaction/readability:** Design direct port targets are at least `24x24`, dense clusters at least `32x24`, and keyboard operable. Verify waveform transport is at least `36x36` with `13px` labels at laptop viewports. Map Pins groups Inputs, Outputs, and Clock / Reset and names both/all signals in a conflict.
