# VHDL SSOT (Stop-Ship Export Divergence Fix) Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Make the VHDL shown in the Design surface HDL pane and the `top.vhd` file in the exported Vivado ZIP byte-identical for a given circuit + IO mapping.

**Architecture:** Three divergences exist today. (1) Entity name: HDL pane uses `topEntityName` (project-name-derived), export uses hardcoded `'top'`. (2) Port bindings: HDL pane calls `vhdlFromNetlist` with no board-aware port bindings; export calls it with explicit Basys3 `topPorts/topInputBindings/topOutputBindings`. (3) `rb-project.json` in the ZIP embeds scaffold VHDL from `buildVhdlFromMapping` (no circuit logic). The fix: expose `buildVhdlTopLevelBindings` from `basys3Bundle.ts`, thread `entityName` through the export chain, update the HDL pane to pass board bindings, and replace the `buildVhdlFromMapping` path with a circuit-derived call.

**Tech Stack:** TypeScript, Vitest, `packages/rb-apps`
