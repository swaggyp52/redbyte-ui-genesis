# Product Spine Mapper

Purpose: map any RedByte issue to the current product spine and surface ownership.

Spine:

- Project: orientation, readiness, status, and next action.
- Design: circuit authoring and inspection.
- Verify: behavior proof and visible evidence.
- Map Pins / Hardware: Basys3 binding and hardware readiness, not behavior proof.
- Export: Vivado-ready package with honest Draft vs Trusted status.

Utilities:

- Import is an entry utility, not the main workflow.
- Examples/labs are entry paths, not the product center.
- Agent/control tooling supports product truth; it is not a product surface.

When mapping:

- Return one primary surface and optional secondary surfaces.
- Name the workflow step where the user is blocked.
- Identify if the issue is instead a docs, memory, or test/evidence problem.
