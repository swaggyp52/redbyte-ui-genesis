# sim-engine agent

## Domain Ownership
This agent owns the simulation engine, verification runtime, and bring-up vector generation.

## Primary Files
- `packages/rb-apps/src/apps/ide/sim/simEngine.ts` — core sim: `buildVerifyRowsFromRuntimeTrace`, `TickEngine`, `TraceRecorder`
- `packages/rb-apps/src/apps/ide/projectRuntime.ts` — Zustand store wiring sim + verify state
- `packages/rb-apps/src/apps/ide/bringupArtifacts.ts` — auto-generates bring-up test vectors
- `packages/rb-apps/src/apps/ide/verifyReport.ts` — `buildVerifyTickSignalIndex`, `VerifyReport` shape
- `packages/rb-apps/src/apps/ide/surfaces/VerifySurface.tsx` — consumes `RuntimeVerifyRun` to render waveform/results

## Key Constants
- `SIM_TRACE_CAPACITY = 256` — max ticks kept in TraceRecorder ring buffer
- Default clock period = 10ns in VHDL export, 1 tick per evaluation in sim

## RuntimeVerifyRun Type
```typescript
interface RuntimeVerifyRun {
  status: 'pass' | 'fail';
  report: VerifyReport;           // tick-indexed rows with pass/fail
  waveform: VerifyWaveSample[];   // sparse — only ticks where vectors exist
  schedule: 'combinational' | 'clocked_macro';
  scenarioId: string;
  scenarioName: string;
  deterministicHash: string;
  reportHash?: string;
  generatedAtIso: string;
  firstFailingTick?: number;
  meta: VerifyRunMeta;
}
interface VerifyWaveSample {
  tick: number;
  signals: Record<string, string>;  // signal key → '0' | '1' | 'X' | 'Z'
}
```

## buildVerifyRowsFromRuntimeTrace (KEY BUG TARGET)
Located in `simEngine.ts`. This function:
1. Receives `vectors: TestVector[]` + full `traceByTick: Map<number, TraceSnapshot>`
2. **BUG**: Only loops through `vectors` — produces one row per (vector × expected output)
3. Result: waveform is sparse (only vector tick positions), even if sim ran 256 ticks

**Fix approach (B.2):**
- After running `buildVerifyRowsFromRuntimeTrace`, build a separate `traceWaveform` from ALL ticks in `state.sim.trace`
- Add `traceWaveform?: VerifyWaveSample[]` to `RuntimeVerifyRun`
- In VerifySurface, use `traceWaveform` (all ticks) for waveform x-axis; use sparse `waveform` only for PASS/FAIL markers

## projectRuntime.ts Actions
Key action methods and their locations:
- `runVerification(input)` — builds verify rows, sets `verifyLastRun`, stores in history
- `clearVerification()` — clears `verifyLastRun`
- `generateBringUpVectors()` — calls `bringupArtifacts.generateBringUpVectors()`, sets `projectVectors`
- `setVectors(vectors)` — manual vector authoring, sets `projectVectors`
- `actions.sim.run/pause/step/reset/setSpeed/setInput/toggleProbe` — simulation control

## bringupArtifacts.ts
`generateBringUpVectors({ ioRows, circuit, existingVectors })`:
- For sequential circuits (hasDff): generates 18 clocked vectors (0→17)
- For combinational circuits: generates 2^N combinations (N = input count, max 6)
- Returns `TestVector[]` — note these have NO `_source` metadata field in the type

**B.3 fix**: Track whether vectors came from `generateBringUpVectors()` by adding `vectorsAreAutoGenerated: boolean` to `ProjectRuntimeState`. Set `true` in `generateBringUpVectors()`, `false` in `setVectors()` and `loadFromProject()`.

## VerifyReport Shape


## Determinism Constraints
- Simulation must be reproducible given the same circuit IR + input sequence
- `deterministicHash` = digest of `exportProject` (circuit + ioMapping + vectors)
- A stale result (hash mismatch) is shown as `STALE` in VerifySurface
- Never mutate sim state directly — use the Zustand actions

## Common Tasks
- **Fix tick mismatch in verify**: Extend `RuntimeVerifyRun` with `traceWaveform`, populate in `runVerification()`
- **Change simulation speed**: Edit `TickEngine` timing constants
- **Add new signal role**: Update `VerifyRunMeta.signalRoles` mapping
- **Debug bring-up generator**: Edit `bringupArtifacts.ts` pattern logic
- **Understand verify flow**: `runVerification() → buildVerifyRowsFromRuntimeTrace() → buildVerifyReport() → setVerifyLastRun()`
